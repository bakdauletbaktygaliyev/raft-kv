## Lesson
### Why this matters in the project
Almost every Raft rule is "given this state and this input, expect that output". Table-driven tests are how you will test `raft/` (vote rules, log matching, commit index), `wal/` framing and `kv/` dedup. Getting the shape right now pays off for hundreds of cases later.

### Mental model
A test function `TestXxx(t *testing.T)` in a `_test.go` file. Instead of one test function per case, you write a **slice of cases** (inputs + expected output, each with a name) and **one loop** that runs each case as a **subtest** with `t.Run(name, ...)`. Adding a case = adding one line to the table.

### Key concepts
- `t.Run(name, func(t *testing.T) {...})` — subtest; failures show `TestX/name`; run one with `go test -run 'TestX/name'`.
- `t.Errorf` (records failure, continues) vs `t.Fatalf` (stops this (sub)test). In tables, `Errorf` lets you see all failing cases at once.
- Message format convention: `Func(input) = got, want want`.
- Anonymous struct slice: `tests := []struct{ name string; in, want int }{ ... }`.
- Internal test (`package raft`) sees unexported names; external (`package raft_test`) sees only the public API. Use internal for now.

### Worked example (a different function)
```go
func Clamp(x, lo, hi int) int { ... }

func TestClamp(t *testing.T) {
	tests := []struct {
		name      string
		x, lo, hi int
		want      int
	}{
		{"inside", 5, 0, 10, 5},
		{"below", -3, 0, 10, 0},
		{"above", 42, 0, 10, 10},
		{"at lower bound", 0, 0, 10, 0},
	}
	for _, tt := range tests {
		t.Run(tt.name, func(t *testing.T) {
			if got := Clamp(tt.x, tt.lo, tt.hi); got != tt.want {
				t.Errorf("Clamp(%d, %d, %d) = %d, want %d", tt.x, tt.lo, tt.hi, got, tt.want)
			}
		})
	}
}
```

## Task
In `raft/quorum.go` write `Quorum(n int) int`: the number of votes that is a majority of a cluster of `n` nodes. In `raft/quorum_test.go` write a table-driven test for it. **You write both** (Learn task).

## Direction
A majority is *more than half*. Think about which cases catch the classic off-by-one: an even `n`. Raft uses this for elections (§5.2) and commit (§5.3): a 3-node cluster needs 2, a 5-node cluster needs 3. Give the function a doc comment ("Quorum returns ...").

## Pseudocode
```
Quorum(n) = smallest integer strictly greater than n/2
table: n = 1, 2, 3, 4, 5, 7 with expected values
loop: t.Run(name) → compare got vs want → t.Errorf on mismatch
```

## Pitfalls and common mistakes
- `n/2` alone is wrong (integer division: 3/2 = 1). `(n+1)/2` is wrong for even `n` (4 → 2, a tie, not a majority).
- Test names: use something readable like `"3 nodes"`, not just `"1"`.
- Let it fail once on purpose (change a `want`) to see what the output looks like.
