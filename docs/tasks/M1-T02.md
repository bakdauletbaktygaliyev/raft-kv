## Lesson
### Why this matters in the project
The Makefile (M1-T05), lint (M1-T06), CI (M1-T08) and protobuf generation (M5, ADR-004) call these tools by name. If they are not on PATH, or were built by a different Go, `make lint` fails in confusing ways.

### Mental model
`go install pkg@version` downloads source, compiles it with **your current Go**, and writes the binary to `GOBIN` (default `$(go env GOPATH)/bin` = `~/go/bin`). Go never touches PATH: if `~/go/bin` is not on PATH, the shell cannot find what you installed.

### Key concepts
- **GOPATH/bin**: where `go install` puts binaries. `go env GOPATH` → `~/go`.
- **`@latest` vs a pinned version**: `@latest` is fine on your laptop; CI pins versions so results are reproducible.
- **`go version <binary>`**: prints which Go built a binary. Tools built by an older Go can break when they read code that uses newer language features (golangci-lint and gopls are sensitive to this).
- **golangci-lint is an exception**: its docs advise *against* `go install` and recommend a release binary or Homebrew.

### Worked example (your machine)
```
$ ls ~/go/bin
dlv gopls protoc-gen-go protoc-gen-go-grpc staticcheck ...   # already there
$ which protoc-gen-go gopls
not found                                                     # ~/go/bin is not on PATH
$ go version ~/go/bin/protoc-gen-go
go1.23.12                                                     # built by an old Go
```
`golangci-lint` and `govulncheck` are not installed at all. `buf` and `protoc` are already installed by Homebrew.

## Task
Put `~/go/bin` on PATH, install `govulncheck` and `golangci-lint`, and rebuild the Go tools you will use (`protoc-gen-go`, `protoc-gen-go-grpc`, `gopls`, `staticcheck`, `dlv`) with Go 1.27.

## Direction
1. Add one line to `~/.zprofile` that appends `$(go env GOPATH)/bin` (or `$HOME/go/bin`) to PATH. Put it **after** the `brew shellenv` line so `go` itself is found first.
2. `go install` the Go-based tools with `@latest`.
3. Install golangci-lint with Homebrew.
4. Open a new terminal and verify.

## Pseudocode
```
~/.zprofile:  export PATH="$PATH:$HOME/go/bin"
go install golang.org/x/vuln/cmd/govulncheck@latest
go install google.golang.org/protobuf/cmd/protoc-gen-go@latest
go install google.golang.org/grpc/cmd/protoc-gen-go-grpc@latest
go install golang.org/x/tools/gopls@latest
go install honnef.co/go/tools/cmd/staticcheck@latest
go install github.com/go-delve/delve/cmd/dlv@latest
brew install golangci-lint
new terminal → run the checks below
```

## Example on a similar problem
Rust does the same thing: `cargo install ripgrep` writes to `~/.cargo/bin`, and `~/.cargo/env` (sourced from your `~/.zshenv`) adds that directory to PATH.

## Pitfalls and common mistakes
- Prepending (`$HOME/go/bin:$PATH`) means a stray tool in `~/go/bin` shadows the Homebrew one with the same name. Appending is safer.
- Editing `~/.zshrc` instead of `~/.zprofile` works in terminals but not for GUI apps or editors that only start a login shell. Keep PATH setup in one place.
- Quoting: `export PATH="$PATH:$HOME/go/bin"`. Without quotes, a path with spaces breaks.
- Checking in the old terminal (same lesson as M1-T01).
