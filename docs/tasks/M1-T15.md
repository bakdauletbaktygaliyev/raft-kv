## Lesson
### Why this matters in the project
The Raft log is a slice that is constantly sliced, truncated and appended to. If the entries you hand to a peer or to `Ready` share an array with the log, a later truncate-and-append overwrites them while they are still in use: a follower receives entries that silently changed. No crash, and the test that catches it fails only on some seeds.

### Mental model
A slice is a small header with three fields: **pointer** to an array, **len** (elements visible), **cap** (room from the pointer to the end of the array). `s[:2]` makes a new header pointing at the **same array**. Copying a slice variable copies the header, not the elements.

`append` has two behaviours:
- `len < cap`: writes into the existing array, in place. Anyone sharing that array sees the change.
- `len == cap`: allocates a new, bigger array and copies. The result no longer shares anything with the old slice.

So the same line of code may or may not alias, depending on spare capacity.

### Key concepts
- `len(s[:2])` is 2, but `cap` is still the rest of the array: that spare room is where `append` writes.
- `slices.Clone(s)`: a new array with the same elements. The usual fix.
- `copy(dst, src)`: copies `min(len(dst), len(src))` elements; `dst` must already have a length.
- Full slice expression `s[:2:2]` sets cap to 2, so the next `append` must reallocate. Reads still share the array, so writes through `s[i] = x` are still visible.
- Always write `s = append(s, x)`: the result may be a different array.

### Worked example (different data, output checked with Go 1.27)
```go
names := []string{"a", "b", "c", "d"}
first := names[:2]            // len 2, cap 4
first = append(first, "X")    // room available: writes into names' array
fmt.Println(names)            // [a b X d]   <- "c" is gone

names = []string{"a", "b", "c", "d"}
safe := slices.Clone(names[:2])
safe = append(safe, "X")
fmt.Println(names)            // [a b c d]
```

## Task

3. Fix `Head`. See the test pass.

## Direction
The test needs a `log` with more than `n` entries; otherwise `append` reallocates and the bug hides. Add doc comments to every exported name, saying in `Head`'s comment that the result does not share memory with `log`.

## Pitfalls and common mistakes
- Test with `n == len(log)`: cap is full, `append` reallocates, and the test passes even with the bug.
- Comparing slices with `==` does not compile; use `slices.Equal`.
- A test that only compares `Head`'s result misses the bug. The check is on the **original**.
