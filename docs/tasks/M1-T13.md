## Lesson
### Why this matters in the project
The README is the first thing a recruiter or reviewer sees. Even at "nothing works yet", it should say what this will be, why it is different, and be honest about status. M6 turns it into the full portfolio README (diagram, GIF, bug log).

### Key concepts
- Order that works for portfolio READMEs: name + badges → one-paragraph pitch → status → how to build/run → (later) how it works, how it's tested → license.
- **Honest status** beats promises: say "walking skeleton, Raft not implemented yet" and link the plan.
- CI badge URL: `https://github.com/<user>/<repo>/actions/workflows/ci.yml/badge.svg`, linked to the workflow page.
- MIT license: short, permissive; matches dependencies (Apache-2.0 / BSD-3 / MIT, see 01-architecture.md). GitHub detects `LICENSE` and shows it in the sidebar.

### Read more
- https://choosealicense.com/licenses/mit/
- https://docs.github.com/en/actions/monitoring-and-troubleshooting-workflows/adding-a-workflow-status-badge
