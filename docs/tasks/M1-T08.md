## Lesson
### Why this matters in the project
CI is the referee for the whole project: later it runs 100 chaos seeds per push and the seed-twice hash check. Starting with lint + race tests means `main` is never red without you noticing, and the green check is visible to anyone looking at the repo (portfolio).

### Mental model
A **workflow** is a YAML file in `.github/workflows/`. **Triggers** (`on:`) say when it runs; **jobs** run in parallel on fresh VMs (`runs-on: ubuntu-latest`); each job is a list of **steps** — either `uses:` (a reusable action, e.g. checkout) or `run:` (shell commands). Nothing is installed by default except what the runner image has, so the first steps are always checkout + setup-go.

### Key concepts
- `actions/checkout` — clones the repo into the VM.
- `actions/setup-go` with `go-version-file: go.mod` — installs the Go version from `go.mod` (here 1.27.x), so local and CI match. It also caches modules/build by default (explored in M1-T09).
- `golangci/golangci-lint-action` — installs a **pinned** golangci-lint version (same as local: v2.15.0) and runs it; prints issues as PR annotations.
- Action versions (`@v7`) are pinned to major versions; checked 2026-11-05: checkout v7.0.1, setup-go v7.0.0, golangci-lint-action v9.3.0.
- `permissions: contents: read` — least privilege for the workflow token.
- Two jobs (lint, test) run in parallel and show as two checks.

## Task
Create a public GitHub repo `raft-kv`, add `.github/workflows/ci.yml` (given in chat 2026-11-05), push, and get a green check.

## Pitfalls and common mistakes
- Wrong directory: must be exactly `.github/workflows/` (plural, leading dot).
- YAML indentation is significant; use spaces, never tabs.
- Local golangci-lint version ≠ CI version → different results. Keep them equal; bump both together.
- `-race` needs cgo; ubuntu runners have gcc, so it works.

## How to verify
- [ ] Actions tab shows the run; both `lint` and `test` jobs green
- [ ] the commit on GitHub shows a green check
