## Lesson
### Why this matters in the project
The folders are the architecture: `raft/` must not import `node/` or `transport/`, `sim/` drives `server/` without real goroutines or clocks. Creating the packages now (empty, documented) makes those boundaries visible from day one and gives the Makefile, lint and CI something to run on.

### Mental model
In Go, **one directory = one package**. The import path is module path + directory (`github.com/bakdauletbaktygaliyev/raft-kv/raft`). A `doc.go` file holds only the package clause and the **package comment**, which `go doc` and pkg.go.dev show as the package description. A directory whose package is `main` builds a binary and must have `func main()`.

### Key concepts
- **Package comment**: a `//` comment directly above `package x`, starting with "Package x ...". One per package (by convention in `doc.go`).
- **Package names**: short, lower-case, no underscores, same as the directory name.
- **`cmd/<name>/`**: the Go convention for binaries; `package main`.
- **Exported vs unexported**: capitalized names are visible to other packages (matters from M1-T14 on).
- `go vet` checks for suspicious code; on empty packages it just confirms everything parses and type-checks.

### Worked example
```go
// Package raft implements the Raft consensus algorithm as a
// deterministic state machine: no goroutines, clocks or I/O.
// Callers feed it ticks and messages and act on what it returns.
package raft
```
```go
// Command raftkv runs one node of the replicated key-value store.
package main

func main() {}
```

## Example on a similar problem
The standard library: `go doc net/http | head` shows its package comment ("Package http provides HTTP client and server implementations.") — that is exactly what your `doc.go` produces for `go doc ./raft`.

## Pitfalls and common mistakes
- `package main` without `func main()` → `function main is undeclared in the main package`.
- Package name not matching the directory (`package raftcore` in `raft/`) — legal but confusing; don't.
- A blank line between the comment and `package` detaches the comment: it is no longer the package comment.
- Comment starting with something other than "Package raft ..." (or "Command raftkv ..." for binaries) — linters flag this later.
