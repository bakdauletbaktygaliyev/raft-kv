## Lesson
### Why this matters in the project
Every real node (Docker Compose in M5) starts from this config: its ID goes into the WAL header (ADR-007), `--peers` is the static membership, and `--bootstrap` is the safety switch that stops a wiped node from rejoining with an empty vote. Getting validation right now prevents confusing failures later.

### Mental model
Parsing is a **pure function**: `args + env → Config or error`. `main` only wires the real `os.Args`, `os.Getenv`, prints, and chooses the exit code. That makes the parser testable without touching the process.

### Key concepts
- `flag.NewFlagSet(name, flag.ContinueOnError)` — a local flag set; returns errors instead of calling `os.Exit` (the global `flag.Parse` exits on error, which you can't test).
- Env fallback = use the env value as the flag's **default**. Precedence: flag > env > built-in default.
- Go's `flag` accepts both `-id` and `--id`.
- `-h` returns `flag.ErrHelp` → exit 0. Bad config → exit 2 (usage error convention).
- Peers stored as a **slice sorted by ID**, not a map: map iteration order is random, and printing/iterating it would be non-deterministic (same rule as the simulator).
- `cmp.Compare(a, b)` in `slices.SortFunc` — never `int(a - b)` on unsigned ints (underflow).
- Injecting `getenv func(string) string` instead of calling `os.Getenv` = dependency injection in its smallest form.

## Pitfalls and common mistakes
- `flag.Parse()` on the global set inside library code: exits the process, untestable.
- Forgetting that `--id` must appear in `--peers` (a node not in its own cluster).
- Duplicate IDs in `--peers`.
- Env bool parsing: only the exact string `true` enables bootstrap here — deliberate, it is a dangerous switch.
