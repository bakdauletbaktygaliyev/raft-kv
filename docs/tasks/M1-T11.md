## Lesson
### Why this matters in the project
M5 runs three nodes with Docker Compose, and CI will build the image on every push. A small, static, non-root image is the baseline.

### Mental model
**Multi-stage build**: stage 1 has the full Go toolchain (~300 MB) and compiles; stage 2 starts from an almost empty image and copies in only the binary. The final image contains only the last stage.

### Key concepts
- `CGO_ENABLED=0` → fully static binary, runs without libc, so a minimal base image works.
- `-trimpath` removes local paths from the binary (reproducible builds); `-ldflags="-s -w"` strips debug symbols (smaller).
- `gcr.io/distroless/static-debian12:nonroot` — no shell, no package manager; has CA certs, `/etc/passwd`, tzdata; runs as UID 65532. Smaller attack surface than alpine. (Debugging: no shell; use `docker cp` or a `:debug` tag if ever needed.)
- Copy `go.mod` (and later `go.sum`) and run `go mod download` **before** `COPY . .` → dependency layer stays cached when only code changes.
- `.dockerignore` keeps `.git`, `docs`, `bin` out of the build context.
- `ENTRYPOINT ["/raftkv"]` (exec form): `docker run image --id 1 ...` passes flags straight through; signals reach the process directly (matters for shutdown in M5).

### Worked example
Tested on 2026-11-05 (Docker 29.2.1): image 8.45 MB; flags and `-e RAFTKV_*` env both work; no args → `--id is required`, exit 2.

## Pitfalls and common mistakes
- Forgetting `CGO_ENABLED=0` → binary needs libc → `exec /raftkv: no such file or directory` on distroless/scratch.
- `COPY . .` before `go mod download` → dependencies re-downloaded on every code change.
- Default `--data-dir data` resolves to `/data` relative to `/` and is not writable for `nonroot` — fine now (nothing written); M5 mounts a volume and sets `RAFTKV_DATA_DIR`.
- Builder Go version must match go.mod (`golang:1.27.3-alpine`).

## How to verify
